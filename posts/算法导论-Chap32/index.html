字符串匹配

与公共子序列不同，字符串匹配要求找到连续的相同段。

几个简单的匹配方法

偏移：段 PPP 在文本 TTT 中出现的位置是以 s+1s+1s+1 开始的，则称偏移为 sss。
文本 TTT a b c a b a a b c a b a c
段 PPP   →s=3\xrightarrow{s=3}s=3​ a b a a

朴素算法

每次 s++ 就进行一次比对，复杂度是 O((n−m+1)m)O((n-m+1)m)O((n−m+1)m)。

Hash 匹配

先计算段 PPP 的 Hash，然后每次 s++ 就计算一次文本 TTT 长度和 PPP 相同的 Hash，再进行比对。

与朴素算法相比，Hash 匹配引入了类似滑动窗口的技术，简单来说，每次偏移增加，就减去移出窗口字符的 Hash，再加上进入窗口字符的 Hash。这可以看作是常数时间的操作。

如图，在计算出相同 Hash 后，才会对这个命中点进行字符串匹配。

自动机方法

本质是对状态的记录

按照逐字符匹配的思路，对段 PPP 构建状态：已匹配字符数。

自然地，需要当前的状态 (已匹配字符数) 和下一个字符 (逐字符比对) 来确定下一个状态。

状态转移示意

状态 输入 a 输入 b 输入 c PPP (目标段)
0 1 0 0 a
1 1 2 0 b
2 3 0 0 a
3 1 4 0 b
4 5 0 0 a
5 1 4 6 c
6 7 0 0 a
7 1 2 0

匹配时，每接受一个来自文本 TTT 的字符，就更新一次状态，直到完全匹配 (状态值等于 PPP 的长度)。

通过记录状态可以知道已经有多少个字符匹配，因此在接受新字符时就可以直接拿 “已匹配的字符 + 接受的字符” 来进行比对，这样需要比对的字符只有一个，且不用回头分析之前的字符，节省了很多时间。

KMP 算法 (Knuth-Morris-Pratt algorithm)

我们发现，构造自动机，直觉上需要 O(mn)O(mn)O(mn) 的时间 (mmm 为 PPP 的长度，nnn 为不同字符个数)，这从表格有 mnmnmn 个元素就能看出。KMP 算法就是对预处理进一步优化的自动机方法。

(实际上朴素方法是 O(m3n)O(m^3 n)O(m3n))

先来看自动机是怎么构建的：
检查文本字符和段的下一个字符是否匹配
1. 匹配，记录状态
2. 不匹配，需要知道“跳转到哪个状态”。朴素方法仅仅删除一个字符再比对 (ABABA 和 ABABC →\rightarrow→ BABA 和 ABAB)

(显然，如果直接跳转到 ABA 和 ABA，就能省一步)

另一种自动机

利用 π\piπ 数组进行字符串匹配

KMP 引入了前缀函数 π\piπ 数组。
π[q]\pi[q]π[q] 的定义如下：在段 PPP 的前 qqq 个字符构成的子段中，最长的相等的真前缀和真后缀的长度。

例如，段 P = "ABABA" 的 π\piπ 数组：

  • q=1 (“A”): 没有真前缀和真后缀，π[1]=0\pi[1] = 0π[1]=0。
  • q=2 (“AB”): π[2]=0\pi[2] = 0π[2]=0。
  • q=3 (“ABA”): 前缀 “A” 和后缀 “A” 相等，π[3]=1\pi[3] = 1π[3]=1。
  • q=4 (“ABAB”): 前缀 “AB” 和后缀 “AB” 相等，π[4]=2\pi[4] = 2π[4]=2。
  • q=5 (“ABABA”): 前缀 “ABA” 和后缀 “ABA” 相等，π[5]=3\pi[5] = 3π[5]=3。

有了这个数组，如果第 5 个字符不匹配，可以直接让文本长度退回到 π[5]=3\pi[5] = 3π[5]=3 继续比对即可。(注意，这是进行字符串匹配时的操作，使用 π\piπ 数组进行字符串匹配，时间复杂度和自动机相同，均为 O(n)O(n)O(n))

优化自动机构建

计算 π\piπ 数组

如果用朴素的方法去算这个 π\piπ 数组，我们需要对每一个 qqq 都进行字符串比对，时间复杂度依然是可怕的 O(m3)O(m^3)O(m3)。与刚才的方法相似，可以借助 π[q−1]\pi[q-1]π[q−1] 计算 π[q]\pi[q]π[q]。

已知 π[q−1]\pi[q-1]π[q−1]，要计算 π[q]\pi[q]π[q]，只需观察第 π[q−1]+1\pi[q-1] + 1π[q−1]+1 和第 qqq 个字符，

例如，段 P = "ABACABAB" 的 π\piπ 数组：

已知 π[7]=3\pi[7] = 3π[7]=3，要计算 π[8]\pi[8]π[8]，发现第 3+13 + 13+1 个 字符和第 888 个不同，不能直接得出 π[8]\pi[8]π[8]，

第 π[7]=3\pi[7] = 3π[7]=3 后面的字符不行，就直接跳转到长度为 π[3]=1\pi[3] = 1π[3]=1 的情况，即观察第 π[3]+1\pi[3] + 1π[3]+1 和第 888 个字符。

发现是相同的，那么加上这个新字符，共有 222 个字符，这就是答案，π[8]=2\pi[8] = 2π[8]=2。
